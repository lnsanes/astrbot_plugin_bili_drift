# astrbot_plugin_bili_drift

让机器人**自己逛 B 站**，而不是等你叫它。

盲刷首页、搜自己的兴趣、追关注的 UP，看简介热评弹幕和封面，**看完才说话**，把觉得有意思的梗和内容记下来，攒够了一次性私聊发给你。

## 设计取向

这套东西的核心不是"定时发消息"，是三个能力：

| 能力 | 实现 |
|---|---|
| **自主时机** | 后台按概率轮询，不是等命令触发 |
| **真实过程** | 点开视频看，不是只看标题 |
| **主观取舍** | 觉得没意思就不发，宁可不刷 |
| **长期积累** | 记住自己的口味和已经看过的梗 |

## 命令

```
/刷一下     手动催一次（平时不用发，它自己会刷）
```

## 工作流程

```
挑一个模式
  ├─ 盲刷：拉首页推荐流随机点进去
  ├─ 兴趣：按记录的偏好搜关键词
  └─ 追更：看关注 UP 有没有新投稿
        ↓
看内容（标题 / UP / 简介 / 热评 / 弹幕 / 封面）
        ↓
要不要深看？
  ├─ 时长 ≤ 900 秒 且 命中 30% 概率 → yt-dlp 下载 ≤480p + 抽 6 帧多模态理解
  └─ 否则只看文本
        ↓
值不值得说？
  ├─ 有意思 → 写进待发队列
  └─ 没意思 → 什么都不做（这一轮等于白刷）
        ↓
攒够了 → 私聊发给主人
```

## 为什么"看完才说话"

直接拿标题生成一段感想，出来的东西一眼假——模型没看过内容，只能编。

所以流程强制要求：**先拿到真实内容（简介、热评、弹幕，必要时抽帧），再组织语言**。

## 配置要点

在 AstrBot WebUI 的插件配置页里：

- **兴趣词**：它搜什么、追谁
- **轮询间隔**：多久看一次
- **深看概率**：多大比例的视频会去下载抽帧
- **推送对象**：默认发给主人私聊

## 依赖

- `yt-dlp`、`ffmpeg`（深看时用）
- 多模态模型（看画面）
- `astrbot_plugin_bili_browse`（共用一部分 API 封装）
